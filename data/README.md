# Data

This directory contains local inputs, processed datasets, generated arguments and evaluation outputs used by the restaurant and hotel pipelines.

The repository does not include the full Yelp dataset, the private hotel dataset or large generated outputs. Only small examples and empty directory placeholders are versioned.

## Directory structure

```text
data/
├── raw/         # Local source datasets
├── processed/   # Intermediate files and experimental outputs
└── examples/    # Small versioned examples
```

Detailed execution instructions are available in:

- [`scripts/restaurants/README.md`](../scripts/restaurants/README.md) for Yelp and CoRAL;
- [`scripts/hotel/README.md`](../scripts/hotel/README.md) for hotel evaluation, ranking and contestation.

## `raw/`

This directory stores source datasets that must remain local and are not committed to Git.

### Yelp

Download the [Yelp Open Dataset](https://business.yelp.com/data/resources/open-dataset/) and place these files in `data/raw/`:

```text
data/raw/yelp_academic_dataset_business.json
data/raw/yelp_academic_dataset_review.json
```

The current subset-construction script reads these two files directly. The Yelp user file is not required by this pipeline.

The first processed subset can then be generated with:

```bash
python -m scripts.restaurants.build_yelp_subset \
  --output data/processed/yelp_subset_500.jsonl \
  --nb-users 500 \
  --history-size 5 \
  --min-user-reviews 6 \
  --seed 42
```

### Hotels

The hotel reviews, metadata, facilities and policies used during the project were provided by Jinko and are not distributed in this repository.

Data extraction, cleaning, exploration, automatic annotation and hotel-profile construction were performed separately in notebooks delivered to the company. These notebooks and the underlying data are not included in the public repository.

The public hotel pipeline expects already prepared files, principally:

```text
hotel_profiles_complete.json
hotel_review_annotations.jsonl    # Optional for cross-file validation
```

These files may be stored in a suitable local directory, including `data/raw/` or `data/processed/`, but their paths are always passed explicitly to hotel scripts.

## `processed/`

This directory stores generated datasets, intermediate representations and experimental results. Its contents can be large and should normally remain outside version control.

### Yelp and CoRAL files

| File pattern | Description | Main producer |
|---|---|---|
| `yelp_subset*.jsonl` | User histories and held-out target restaurants | `scripts.restaurants.build_yelp_subset` |
| `*_with_review_aspects_nli.jsonl` | Yelp records enriched with detected review aspects | `scripts.restaurants.extract_review_aspects_nli` |
| `aspect_mf_dataset*.csv` | User–aspect–rating training data | `scripts.restaurants.build_aspect_mf_dataset` |
| `aspect_mf_predictions*.json` | Aspect-MF predictions used as empirical signals | `scripts.restaurants.train_aspect_mf` |
| `generated_arguments_*.jsonl` | Raw structured arguments generated by the LLM | `scripts.restaurants.generate_batch` |
| `*_valid.jsonl` | Generated outputs accepted by validation | `scripts.restaurants.generate_batch` |
| `*_invalid.jsonl` | Rejected outputs and validation information | `scripts.restaurants.generate_batch` |
| `scored_arguments_*.jsonl` | Valid arguments with semantic, empirical and combined strengths | `scripts.restaurants.score_batch` |
| `dfquad_*.jsonl` or `coral_*.jsonl` | Argument graphs, aggregations and recommendation scores | `scripts.restaurants.dfquad_batch` |
| `mf_item_dataset*.csv` | User–restaurant training data for the MF-only baseline | `scripts.restaurants.build_mf_dataset` |
| `mf_item_predictions*.json` | Global MF predictions for target restaurants | `scripts.restaurants.train_mf` |
| `llm_direct_scores_*.jsonl` | Direct scores produced by the LLM-only baseline | `scripts.restaurants.llm_direct_score` |
| `yelp_ranking_candidates_*.jsonl` | Ranking groups with one held-out target and comparison candidates | `scripts.restaurants.build_ranking_candidates` |
| `evaluation_*.csv` | Per-example rating or ranking results | Evaluation scripts |
| `evaluation_*_summary.json` | Aggregated MAE, RMSE, Hit Rate, MRR or NDCG values | Evaluation scripts |
| `yelp_contested_*.json` | Score recomputed after changing one argument strength | `scripts.restaurants.contest_yelp_argument` |

Most scripts also create a companion summary file whose name ends in `_summary.json`.

### Hotel files

| File or directory pattern | Description | Main producer |
|---|---|---|
| `hotel_validation_summary.json` | Validation and coverage summary for prepared hotel data | `scripts.hotel.validate_hotel_data` |
| `hotel_evaluation*.json` | Complete individual evaluation with eligibility, arguments and DF-QuAD score | `scripts.hotel.evaluate_hotel_session` |
| `hotel_evaluation*.html` | Standalone visual explanation of an evaluation | `scripts.hotel.render_hotel_graph` |
| `hotel_evaluation_contested*.json` | Evaluation recomputed after structured preference edits | `scripts.hotel.contest_hotel_evaluation` |
| `hotel_evaluation_contested*.html` | HTML view of a contested evaluation | `scripts.hotel.contest_hotel_evaluation` |
| `hotel_facility_inventory.json` | Coverage of the canonical facility ontology | `scripts.hotel.inventory_hotel_facilities` |
| `hotel_ranking/` | Session profile, candidate evaluations, HTML reports and final ranking | `scripts.hotel.rank_hotel_session` |

A ranking output directory normally contains:

```text
hotel_ranking/
├── session_preferences.json
├── evaluations/
│   └── HOTEL_ID.json
├── reports/
│   └── HOTEL_ID.html
├── ranking.json
└── ranking.csv
```

Only hotels whose mandatory constraints are explicitly satisfied receive a rank. Candidates marked `unknown` or `ineligible` remain present in the explanatory ranking outputs.

## `examples/`

This directory contains small versioned files used to document expected formats and support quick inspection without downloading the complete datasets.

The current example is:

```text
data/examples/sample_input.jsonl
```

Example files are synthetic or manually constructed and do not redistribute private hotel data or original Yelp records.

## Data handling notes

- Rejected LLM generations should remain separate from validated records and must not be used in argumentative scoring.
- The hotel profiles cannot be regenerated from the public repository alone because their preparation notebooks and source data were delivered separately to Jinko.
